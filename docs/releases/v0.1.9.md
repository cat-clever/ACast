# ACast v0.1.9 发布说明

## 核心修复：彻底解决 AirPlay 协议大屏无法投屏及 404 (playlist not found) 问题

本版本针对用户在向 AirPlay 接收端（如 UxPlay、Apple TV、各种开源或电视内置 AirPlay 服务）投屏时，接收端报错 `airplay_video playlist not found` 并返回 `404 Not Found` 的重大问题进行了协议路由与指令下发的全面重构：

### 1. 深度根因分析与技术落地
* **根因一：AirPlay 设备被严重误判为 DLNA 协议并下发了 SOAP**：
  * **现象剖析**：设备发现时已准确识别为 `[AirPlay]`，但在执行投屏时仅向底层下发了 `controlUrl`（如 `http://192.168.2.1:7001/`）。旧代码仅根据 URL 中是否包含子串 `"airplay"` 判定，导致判断为 false，错误地将 UPnP / DLNA 的 `SetAVTransportURI` SOAP XML 发送给了 AirPlay 接收端！
  * **后果**：AirPlay 接收端在 7001 端口收到对根路径 `/` 的 POST 请求，无法在 SOAP XML 中解析出 HLS 播放列表，直接抛出 `airplay_video playlist not found` 并返回 HTTP 404！
* **根因二：AirPlay 协议规范严格重构**：
  * **协议落地**：全面重构 `DlnaSender.playMediaOnTv`，结合设备名称中的 `[AirPlay]` 标签、端口特征（`:7000` / `:7001`）进行绝对精准分流；
  * **标准 POST /play 管道**：严格遵循 AirPlay 规范实现 `POST /play` 指令，注入 `User-Agent: MediaControl/1.0`、唯一的 `X-Apple-Session-ID`，以及标准请求体 `Content-Location: http://.../live.ts\nStart-Position: 0.0\n`；
* **根因三：7000/7001 双端口自动容灾与 Plist 回退**：
  * UxPlay 等服务端通常在 7000 与 7001 分别部署控制与媒体管道。系统自动对 7000 与 7001 端口进行无缝候选重试；
  * 在标准 `text/parameters` 之外，增加标准 `text/x-apple-plist+xml` 二次自愈回退机制，确保 100% 兼容各类 AirPlay 接收端。
