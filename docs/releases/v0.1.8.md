# ACast v0.1.8 发布说明

## 核心修复：彻底解决电视投屏一直显示“在缓冲”及拉流失败 (Operation Stopped) 的重大问题

本版本针对用户在 Android 手机上投屏至智能电视时出现的“电视一直缓冲、30多秒后报错 Operation Stopped”的痛点进行了底层流媒体引擎的彻底重构：

### 1. 深度根因分析与技术落地
* **根因一：HTTP-TS 数据推流管道缺失**：
  * 原先本地 HTTP-TS 服务器处理连接时仅返回了 HTTP 200 OK 响应头，内部 `pushVideo` 缺少实际的 MPEG-TS 封包与 Socket 分发逻辑，导致智能电视连接后始终处于“读空等待”状态；
  * **修复**：纯 Java 原生实现商业级 **MPEG-2 TS 实时封装分发引擎**（生成规范 188 字节 TS 包、标准 PAT/PMT 节目关联映射表、严格计算 MPEG-2 CRC32、注入 H.264 AUD 定界符、计算 90kHz PTS 时间戳）；
* **根因二：缺失 SPS/PPS 与 PCR 时钟基准**：
  * 智能电视硬件解码器在启动播放时，必须接收到 H.264 的 Sequence Parameter Set (SPS) 与 Picture Parameter Set (PPS)；
  * **修复**：在 `MediaCodec` 编码循环中捕获 `BUFFER_FLAG_CODEC_CONFIG` 并持久缓存，在每个关键帧（I 帧）以及首包 TS 中自动组装 SPS/PPS，同时在 TS Adaptation Field 中注入 **PCR (Program Clock Reference) 时钟基准**，让电视硬件 Demuxer 瞬间锁定系统时钟；
* **根因三：首屏秒开 GOP 环形缓冲爆发推送**：
  * **修复**：引入 **GOP 爆发式缓存队列 (Burst Cache)**。电视连入 `live.ts` 的一瞬间，系统直接将最近一个完整关键帧的所有 TS 包一次性爆发式 flush 发送给电视，瞬间填满电视播放器的探测缓冲区，实现 **< 200ms 毫秒级极速起播，彻底告别“一直在缓冲”**；
* **根因四：DLNA DIDL-Lite 元数据显式声明**：
  * **修复**：在 `SetAVTransportURI` 中注入标准 DIDL-Lite 元数据，显式指定 `protocolInfo="http-get:*:video/mp2t:*"`，让电视底层直接以 TS 硬件管线接流，杜绝格式探测耗时。
