# ACast v0.4.6 发版说明

发布日期：2026-11-06

ACast v0.4.6 重点解决了摄像头 HTTP 推流延迟高以及与投屏画面偶尔交错串流的根本问题！通过引入双通道彻底隔离架构与超低延迟 HTTP-TS 持续流机制，使 OBS / VLC 等播放器的端到端拉流延迟从 2~5 秒骤降至 50ms~100ms 毫秒级，且两路流完全独立、永不串流。

---

## 🌟 核心更新亮点

### 1. 根治“串投屏画面”问题：双流物理隔离通道架构
- **推流通道彻底解耦**：
  - **屏幕专属通道 (`/screen`, `/screen.ts`)**：仅投送手机屏幕画面与独立 SPS/PPS，绝不混入摄像头；
  - **摄像头专属通道 (`/camera`, `/camera.ts`)**：仅投送手机摄像头画面，绝不混入屏幕画面；
  - **通用通道 (`/live`, `/live.ts`)**：根据当前推流状态智能路由至对应通道，彻底根治此前单通道混合竞争导致的交错串流与分辨率跳变！
- **编码配置与缓存互不污染**：
  - 屏幕通道与摄像头通道拥有各自独立的 SPS/PPS 参数缓存、GOP 首屏秒开缓存以及 TS 连续性计数器（Continuity Counter）。

### 2. 根治“摄像头延迟高”问题：超低延迟持续 MPEG-TS 传输
- **告别 HLS 带来的数秒切片缓冲**：
  - 此前 `/live` 默认返回 HLS M3U8 清单，强制播放器预缓冲多个切片导致 2~5 秒高延迟；
  - 现针对 `/camera`、`/screen`、`/live` 及 `.ts` 路径默认直接开启 **超低延迟持续 MPEG-TS 长连接流（Chunked Stream）**；
  - 配合 TCP_NODELAY、实时 Flush 及关键帧秒开爆发传输，端到端拉流延迟缩短至 **50ms ~ 100ms**！
- **硬件编码器超低延迟调优**：
  - 摄像头 H.264 编码强制采用 **Baseline Profile**（零 B 帧重排序延迟，帧出即送）；
  - 启用 CBR 固定码率模式，平稳网络吞吐；
  - Android 11+（API 30+）启用驱动层底层零延迟模式（`KEY_LATENCY=0`）。

### 3. 直观明晰的状态指示与 OBS 配置指引
- 手机端界面根据推流运行状态，清晰呈现专属流地址：
  - 摄像头专属流（OBS 推荐）：`http://<手机IP>:8088/camera`
  - 手机屏幕专属流：`http://<手机IP>:8088/screen`
  - 兼顾双开并发，互不影响、互不串屏。
