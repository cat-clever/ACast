# ACast v0.1.6 发布说明

## 核心更新：集成项目统一签名，彻底解决 Android 安装包签名不一致问题

本版本针对 Android 客户端的应用安装与应用内在线热更新覆盖机制进行了签名层面的彻底标准化：

### 1. 签名不一致根因剖析与解决
* **问题背景**：此前 Android 构建配置使用的是 Gradle 默认 `signingConfigs.debug`。GitHub Actions 云端 Runner 为无状态临时虚拟机，每次流水线构建时生成的临时签名密钥均不相同。导致用户手机在安装旧版本后，通过内置热更新或手动下载新版覆盖时，被 Android 系统底层阻断并报错 `INSTALL_FAILED_UPDATE_INCOMPATIBLE: signatures do not match previously installed version`（应用签名不一致）；
* **项目内嵌统一签名文件**：
  * 生成并在项目中固化统一的 Release 签名库文件 `app-android/app/acast-release.jks`（有效期至 2054 年）；
  * 在 `build.gradle` 中将 `release` 与 `debug` 构建模式统一绑定至该签名配置；
  * 同时全面开启 **V1 (Jar Signature)** 与 **V2 (Full APK Signature)** 双签名协议，保证从 Android 7.0 (API 24) 到 Android 14+ 全版本兼容；
* **效果保证**：
  * 从 v0.1.6 开始，后续所有云端构建与本地发版的 APK 签名指纹完全一致，彻底杜绝签名不一致无法升级的问题；
  * 完美适配应用内静默下载、拉起 PackageInstaller 自动化无感热更新覆盖流程。
