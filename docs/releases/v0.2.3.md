# ACast v0.2.3 发版说明

## 更新亮点

### 彻底攻克 Android DLNA 投屏大屏拉流失败 (Operation Stopped) 的核心根因
* **静止画面恒定推流守护 (`KEY_REPEAT_PREVIOUS_FRAME_AFTER`)**：
  * **根因定位**：当手机处于静止画面（如主屏、ACast 界面）时，Android `VirtualDisplay` 不会向 Surface 提交新帧，导致硬件编码器停产，电视连入后 2 秒内接收不到音视频数据，播放器因缓冲区饥饿断流判定 End of Stream 抛出 `Operation Stopped`；
  * **恒定帧率输出**：为硬件编码器配置 `KEY_REPEAT_PREVIOUS_FRAME_AFTER = 100000L`，画面静止时强制每隔 100ms 自动重复输出上一帧，确保视频流源源不断输出。
* **高频 PCR 时钟锁相环心跳守护 (`generatePcrPacket`)**：
  * 符合 ISO/IEC 13818-1 规范（PCR 间隔必须 <= 100ms），在推流闲暇或队列等待时，每隔 40ms 持续向电视发送 188 字节纯 PCR TS 心跳包，电视 Demux 芯片永远保持时钟同步，彻底杜绝时钟恢复失锁导致的拉流中断。
* **首屏即刻刷新机制 (`PARAMETER_KEY_REQUEST_SYNC_FRAME`)**：
  * 电视建立 HTTP 拉流连接的瞬间，服务端主动向硬件编码器请求即刻刷新 I 帧 (IDR 关键帧)，并连同 PAT/PMT 瞬间填充电视缓冲区，秒开首屏画面。
* **规范 DLNA 实时直播 HTTP 协议标头与 DIDL-Lite 描述**：
  * 增加 `transferMode.dlna.org: Streaming`、`contentFeatures.dlna.org: DLNA.ORG_OP=01`、`ext: ` 及 `Connection: keep-alive`；
  * 严格规范 `HEAD` 探测请求，仅返回标头绝不输出 Body；
  * `DlnaSender` 投屏前执行 `Stop` 复位大屏状态，并在 `SetAVTransportURI` 后预留 500ms 缓冲再发 `Play`，杜绝大屏状态机紊乱。
