# ACast v0.1.7 发布说明

## 核心更新：优化投屏流程，改为先开启投屏然后再点击投屏设备

本版本对 Android 手机端投屏到智能大屏的业务时序与交互流程进行了深度重构与智能联动：

### 1. 业务时序与痛点深度重构
* **痛点根因**：DLNA / Cast / AirPlay 协议体系中，电视端是作为客户端主动向手机本地的 HTTP-TS 端口（8088）请求音画流数据。此前若用户未先点击【开启屏幕投屏】（即本地实时流服务器尚未启动），直接点击搜索出来的电视设备，电视接收到播放地址后去拉取数据会直接因“连接被拒”（Connection Refused）而出现黑屏、退出或报错；
* **操作流程严格规范与智能联动**：
  * **先开启投屏再投设备**：在未开启屏幕投屏时，点击设备列表项将被智能拦截并给出明确提示：`⚠️ 请先开启屏幕投屏！正在为您调起授权...`；
  * **一键无缝自动流转**：拦截后系统会自动记忆目标设备，并直接调起系统录屏授权弹窗。当用户点击“立即开始”授权成功且本地流服务启动后，系统将**自动向该设备下发播放指令**，无需用户再次手动重复点击；
  * **全流程清晰指引**：
    * `1. 开启屏幕投屏`（开启后变为 `1. 停止屏幕投屏`）；
    * `2. 搜索大屏设备 (DLNA / Cast / AirPlay)`；
    * `3. 点击大屏设备开始投屏`（未开启时醒目提示 `⚠️ 请先完成第1步开启投屏`，开启后显示 `✓ 投屏服务已就绪`）。
