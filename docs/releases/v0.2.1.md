# ACast v0.2.1 发布说明

## 紧急修复：彻底解决 macOS 启动时 SIGSEGV (EXC_BAD_ACCESS) 崩溃

本版本针对用户在 macOS 上打开 v0.2.0 时出现的 `EXC_BAD_ACCESS (SIGSEGV)` 崩溃进行了紧急深度定位与全面内存安全重构：

---

### 1. 深度根因分析与技术重构

#### ① 崩溃堆栈精准定位
在用户提供的系统崩溃日志中：
```text
Thread 0 Crashed:: Dispatch queue: com.apple.main-thread
0   ACast 0x104f8986c invocation function for block in -[AppDelegate applicationDidFinishLaunching:]::$_3::operator()(acast::updater::UpdateInfo const&) const + 28
1   libdispatch.dylib 0x18245bb2c _dispatch_call_block_and_release + 32
...
Exception Type: EXC_BAD_ACCESS (SIGSEGV)
Exception Codes: KERN_INVALID_ADDRESS at 0x000000016b1c6ea0
```

#### ② 根因剖析 (C++ 栈帧与 Objective-C Block 异步生命周期冲突)
* 在旧版本 `gui_macos.mm` 中，`SetUpdateCallback` 注册的回调接收了 `const acast::updater::UpdateInfo& info` 常量引用；
* 该回调在后台工作线程中被调用，并随后调用了 `dispatch_async(dispatch_get_main_queue(), ^{ ... info.latest_version ... });`；
* 由于 `dispatch_async` 是非阻塞异步派发到主线程 RunLoop，后台工作线程在派发完成后立即返回并销毁了栈帧中的 `info` 对象；
* 当主线程从 RunLoop 取出 block 开始执行时，block 内部持有的指针指向的是一个**已被销毁的无效栈内存地址**（`0x16b1c6ea0`），从而瞬间触发段错误 `EXC_BAD_ACCESS (SIGSEGV)` 导致应用崩溃！

#### ③ 全面技术重构与防卫落地
1. **C++ 回调签名全面值传递化**：
   * 将 `desktop_controller.h` 中的 `UpdateCallback`, `TvDeviceCallback`, `UsbDeviceCallback`, `LogCallback` 统一改为**值拷贝传递**（Value semantics），杜绝任何跨线程引用逃逸；
2. **异步 Block 显式桥接与 ARC 自动内存托管**：
   * 在进入 `dispatch_async` 闭包之前，提前在回调线程将需要展示的数据显式提取为独立的 Cocoa 原生对象（`NSString*`, `BOOL`, `NSDictionary*`）；
   * Objective-C Block 在被 `dispatch_async` 捕获复制到堆区时，ARC 会自动增加 Cocoa 对象的引用计数，确保无论何时主线程执行 block，内存永远安全有效；
3. **防止 AppKit 弱引用提前回收**：
   * 将 `AppDelegate` 实例提升为全局静态强引用 `static AppDelegate* g_appDelegate`，防止被系统作为弱引用代理析构；
4. **时序安全优化**：
   * 确保主视窗 `[window makeKeyAndOrderFront:nil]` 完全初始化并渲染上屏之后，再启动后台网络发现与更新检查，从根本上杜绝时序竞态。
